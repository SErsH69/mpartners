# Публикация темы

Тема публикуется автоматически: любой push в `main`, который задевает
`theme/`, `assets/`, `package.json`, `yarn.lock` или `webpack.config.js`,
запускает workflow [«Публикация темы»](.github/workflows/deploy-theme.yml).

Что делает workflow:

1. собирает прод-бандл (`yarn install --immutable && yarn prod`) — каталог
   `theme/dist` в репозитории не хранится и создаётся на лету;
2. проверяет, что бандл и шрифт на месте;
3. заливает каталог `theme/` по rsync в `wp-content/themes/mpartners` на
   хостинге (с `--delete`, то есть каталог темы на сервере всегда равен
   содержимому репозитория);
4. проверяет, что главная отвечает 200.

Workflow можно запустить вручную: вкладка **Actions** → «Публикация темы» →
**Run workflow**.

## Секреты

Репозиторий публичный, поэтому доступы лежат в
**Settings → Secrets and variables → Actions**:

| Секрет             | Что это                                            |
| ------------------ | -------------------------------------------------- |
| `DEPLOY_HOST`      | адрес SSH/FTP-сервера хостинга                      |
| `DEPLOY_USER`      | логин FTP-аккаунта с включённым SSH                 |
| `DEPLOY_PASSWORD`  | его пароль                                          |
| `DEPLOY_PATH`      | полный путь до каталога темы на сервере             |

Если на хостинге завести SSH-ключ, пароль можно заменить на ключ: вместо
`sshpass -e rsync …` в workflow используется `ssh-agent` с приватным ключом
из секрета.

## Плагины сайта

Плагины живут только на сервере и деплоем не обновляются:

| Плагин | Зачем |
| ------ | ----- |
| Advanced Custom Fields Pro | поля и блок-фабрика стартового шаблона |
| Contact Form 7 (6.1.7) | формы; разметка задаётся темой в `inc/cf7.php` |
| Yoast SEO | заголовки, canonical, Open Graph, `sitemap_index.xml`, robots.txt |
| Cyr-To-Lat | транслитерация кириллических адресов страниц |

CF7 зафиксирован на 6.1.7: версия 6.2+ требует PHP 8.3, а на хостинге 8.2.

## Где что редактируется

| Что | Где в админке |
| --- | ------------- |
| Контент каждой страницы | в самой странице: **Страницы → нужная → блок «Контент …»** |
| Карточки практик | **Практики** — отдельный тип записей (заголовок, текст, изображение записи, порядок) |
| Пресс-центр | обычные **Записи** с рубриками |
| Мероприятия, СМИ о нас | свои типы записей со своими рубриками |
| Текст внутренней страницы материала | в самой записи — блок «Контент материала» |
| Меню шапки и подвала, список услуг | **Внешний вид → Меню** (три места: шапка, подвал-меню, подвал-услуги) |
| Телефоны, соцсети, адреса, подвал | **Общие настройки** |
| Формы | **Contact Form 7**, но разметка задаётся темой в `inc/cf7.php` |

Поля собираются автоматически из массивов `inc/*-data.php`: строка — текстовое
поле, список — репитер, вложенный массив — группа. Значения из макета остаются
значениями по умолчанию: пустое поле — вернётся текст из макета. При первом
запуске поля и меню заполняются текущим контентом, чтобы редактор открывал
готовые страницы.

Страницы со своими шаблонами открываются в классическом редакторе без блоков —
весь их контент в полях.

## Что деплой не трогает

- ядро WordPress, плагины и загрузки (`wp-content/uploads`) — они живут
  только на сервере;
- статическую копию для GitHub Pages в корне репозитория (`index.html`,
  `dist/`) — она обновляется вручную через `yarn static`.
