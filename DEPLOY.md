# Публикация темы

Тема публикуется автоматически: любой push в `main`, который задевает
`theme/`, `assets/`, `package.json`, `yarn.lock` или `webpack.config.js`,
запускает workflow [«Публикация темы»](.github/workflows/deploy-theme.yml).

Что делает workflow:

1. собирает прод-бандл (`yarn install --immutable && yarn prod`) — каталог
   `theme/dist` в репозитории не хранится и создаётся на лету;
2. проверяет, что бандл и шрифт на месте;
3. заливает каталог `theme/` по rsync в `wp-content/themes/mpartners` на
   хостинге (с `--delete`, то есть каталог темы на сервере всегда равен
   содержимому репозитория);
4. проверяет, что главная отвечает 200.

Workflow можно запустить вручную: вкладка **Actions** → «Публикация темы» →
**Run workflow**.

## Секреты

Репозиторий публичный, поэтому доступы лежат в
**Settings → Secrets and variables → Actions**:

| Секрет             | Что это                                            |
| ------------------ | -------------------------------------------------- |
| `DEPLOY_HOST`      | адрес SSH/FTP-сервера хостинга                      |
| `DEPLOY_USER`      | логин FTP-аккаунта с включённым SSH                 |
| `DEPLOY_PASSWORD`  | его пароль                                          |
| `DEPLOY_PATH`      | полный путь до каталога темы на сервере             |

Если на хостинге завести SSH-ключ, пароль можно заменить на ключ: вместо
`sshpass -e rsync …` в workflow используется `ssh-agent` с приватным ключом
из секрета.

## Что деплой не трогает

- ядро WordPress, плагины и загрузки (`wp-content/uploads`) — они живут
  только на сервере;
- статическую копию для GitHub Pages в корне репозитория (`index.html`,
  `dist/`) — она обновляется вручную через `yarn static`.
